# Copyright rejection: image-first triage

When a video generation reports copyright protection, prioritize the **reference pictures** and tell the user that the first practical change is replacing the suspect image or its recognizable costume with a different everyday/original outfit. Do not begin by blaming fps, resolution, hidden dance-timing blacklists or the length of the prompt.

1. Identify the exact version of each uploaded picture/video/prompt and the last successful result. Give newly changed pictures priority; a previously successful reference is a useful comparison, not permanent approval. If several variables changed, say so without pretending one is proven responsible.
2. View the actual pictures and original outfit references. Look for the combination of whole costume, hairstyle, horns/ears/headwear, accessories, badges/logos and iconic scenery. Verify a named role or source with credible visual evidence when uncertain. A common symbol (e.g. a cross), a generic black dress, a color or a hairstyle alone does not establish an IP match.
3. State what visibly matches and what remains unknown. Input-image, input-video and output-video rejection are different categories; a generic output error is not a backend record naming image4. A platform chatbot's explanation without per-task evidence is not automatically a confirmed moderation trace. Do not issue a definitive legal infringement finding from a resemblance.
4. Recommend changing the **suspect picture / complete recognizable outfit**, rather than only deleting the role name, replacing the face or background, or applying depth. Keep the chosen identity/background/lighting/expression where the user wants them. If replacement is authorized, prepare the replacement; otherwise recommend it without silently editing selected clothing. Do not make repeated paid one-image tests a routine requirement.
5. If image evidence is weak or replacements still fail, inspect the reference video and prompt and obtain task-specific error evidence. Same vendor/model does not establish identical moderation configuration; do not claim one platform is stricter without evidence. If policies were identical, changed inputs/generated outputs could still produce a different outcome.

Depth is for separating motion from appearance, not a copyright-bypass guarantee. Generated-image changes and metadata removal do not establish copyright clearance. Do not claim all IP is banned, give success-rate promises, or invent a character name to explain the rejection.

For this user's prior case: an earlier fox-themed D was suspected to match a known game character; the later black cross dress had **no verified character match**. Keep versions separate. A successful `out_01.mp4` is stronger comparative evidence than speculation about unchanged pictures. These are case observations, not universal platform rules.
