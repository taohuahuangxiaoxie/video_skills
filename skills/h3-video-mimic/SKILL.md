## Production-mode gate

Inventory and visually verify every cut, then classify the media within each interval. A zoom/pan applied to one photograph is not necessarily live motion.

| Source structure | Mode | Production decision |
| --- | --- | --- |
| Continuous action, or a modest sequence of real motion shots | `motion_video` | Generate only the necessary video groups, respecting real cuts and the chosen engine. |
| One/few short action clips plus posed photos, snapshots, photo zooms, or an end-card | `hybrid_motion_stills` | Separate video, still-image, and editorial work. Read [references/hybrid-motion-stills.md](references/hybrid-motion-stills.md). |
| Dense real-motion montage with many sub-second changes | `dense_montage` | Explain fidelity risk; offer documented simplification, experimental approximation, or an authorized motion-reference alternative. Do not mistake this for a photo montage. |

Show the proposed mode, source ranges, deliverable ownership, and reference roles before image generation. Once approved, keep that partition on resume. In hybrid mode, never pass all the stills through H3/Seedance just to fill the source runtime.

## Engine and reference strategy

- For this user's **orbiting camera plus quick turns/jumps and lively performance**, recommend **Seedance** first and provide its adapted prompt. Here `SD` means Seedance, not Stable Diffusion. Record the exact version and surface; do not silently exchange 2.0 and 2.5.
- This preference comes from the user's `task_qcws` comparisons, not a universal ranking. If the user chooses local H3, support that choice with a clearly scoped trial; do not switch engines without agreement.
- For **continuous subject motion plus camera/environment parallax**, default to `role_references`: clean character views + a separate empty location + an optional gesture reference. Do not turn those files into sequential shots or forced first/last frames.
- Choose `keyframe_anchors` only when a specific opening, ending, composition match, transition, or shot boundary actually requires one and the active surface supports it. Extracted analysis frames do not automatically become generator keyframes.
- Resolve visual roles in [references/reference-images.md](references/reference-images.md). Resolve motion and feedback in [references/motion-review.md](references/motion-review.md).

## Stages and gates

1. **Analyze and partition:** probe, inventory cast/cuts, distinguish motion from edited photographs, identify action/camera/expression endpoints, and propose production mode and engine.
2. **Create/reuse images:** follow the reference-image guide. Reuse approved assets; dispatch missing references and standalone still batches to new authorized tasks. New revisions also use new tasks. Main task inspects results and stops for user review by default.
3. **Write the chosen engine's prompt:** H3 → [references/h3-prompts.md](references/h3-prompts.md); Seedance → [references/seedance-prompts.md](references/seedance-prompts.md). Deliver a complete paste-ready prompt and exact ordered asset map, not only an edit fragment or an engine name.
4. **Manual handoff:** follow [references/handoff-assembly.md](references/handoff-assembly.md). Give actual duration, aspect, reference mode, and source-action/hold ranges. H3-specific workflows and pixel multipliers apply only to H3.
5. **Review or finish:** use concrete reported/observed defects for a bounded revision. If the user owns editing, deliver the approved clip instructions, ordered stills, and edit map, then stop; do not keep the task pending for an unrequested FFmpeg merge. If assembly is requested, verify clips and assemble a new version.

## H3-only defaults and suitability

For the user's established local **Ref2VA** branch, default to `03-MiniMax-Ref-Kitchen-Attention`, image-only references, optional `0.3` manual preview, and `0.9` formal pixel multiplier. These are local tested settings, not universal model specifications. An explicit native first/last-frame request requires verifying the actual H3 input mode and using its corresponding schema/workflow; do not assume this Ref2VA graph exposes exact frame binding. Preserve the current acceleration/Attention configuration unless the user asks to test it. Use groups at most 15 seconds and at most seven image references in the tested Ref2VA workflow.

Warnings for dense **motion** montages include more than about seven materially distinct shots per 15 seconds, mostly sub-second cuts, frequent location/wardrobe/face-scale changes, or a demand to recreate every flash frame. Explain every proposed omission or consolidation. Nine-reference wedding tests increased scene leakage; seven was safer but did not solve a 42-cut montage. Do not apply these warnings to a photo tail that will be generated as separate stills.
